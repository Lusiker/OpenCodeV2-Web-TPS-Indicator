# 指标口径

## 采样

| 参数 | 值 | 说明 |
|---|---|---|
| 刷新周期 | 200 ms | 定时器同时驱动标签、面板与时间线 |
| 统计窗口 | 2 000 ms | 实时速度的滑动窗口 |
| 停顿阈值 | 800 ms | 超过后切换为等待状态 |
| 曲线跨度 | 30 000 ms | 面板曲线的时间范围 |

实时速度 = 窗口内估算 token 数 / 窗口实际跨度，跨度下限 300 ms，避免首个增量产生极端值。

## 实时估算

流式增量没有分词器信息，按字符折算：

- 码点大于等于 `0x2E80` 的字符（CJK、假名、谚文、emoji）计 4 个单位。
- 其余字符计 1 个单位。
- 每 4 个单位折算 1 token。

文本、推理与工具参数三类增量都计入，因为它们共用同一次生成过程。

## 精确值

步骤结束事件携带 `tokens.output` 与 `tokens.reasoning`：

```
tokens = output + reasoning
start  = 首个非文本内容片段的 time.created，缺失时用消息的 time.created
end    = 消息的 time.streamed
rate   = tokens / ((end - start) / 1000)
```

页面加载时若步骤已结束，直接读取最后一条完成的 assistant 消息，用同一公式计算，结果与步骤结束时一致。

若最新消息仍在生成，则回退到上一条已完成消息，保持标签有值可显示。

## 面板字段

| 字段 | 实时阶段 | 精确阶段 |
|---|---|---|
| 当前速度 | 2 秒窗口估算 | 整段平均值 |
| 峰值 | 本段实时采样最大值 | 与实时值取较大者 |
| 均值 | 本段估算 token / 从首字到当前的时长 | 精确 token / 整段耗时 |
| 首字 | `session.step.started` 到首个增量的间隔 | 由消息时间戳推算 |
| 本段 | 本段估算 token 数 | `output + reasoning` |
| 耗时 | 从首字到当前的时长 | `streamed - start` |
| 窗口 | 固定显示 2.0 s | 同左 |

步骤失败时若有 token 用量，按结束处理；没有则保留上一次结果。

## 显示格式

- token 数与速度超过 1000 时改用 K，超过 1 000 000 时改用 M，保留两位小数，例如 `12.35K`、`1.23M`。
- 耗时超过 60 秒改用分钟，超过 3600 秒改用小时，避免数值撑破面板栅格。
- 首字延迟超过 60 秒同样改用分钟。

## 曲线

- 每 200 ms 记录一个采样点，空闲期记为 0，曲线因此能看到步骤间隙。
- y 轴上限取 `max(20, 向上取整到 10 的倍数)`，低速时也有可读的高度。
- 数据不足 30 秒时按已有跨度铺满宽度，满 30 秒后转为滚动窗口。
- 曲线只表达形状，精确读数以下方统计与标签为准。

## 误差来源

- 字符折算与真实分词器存在偏差，混合语言与代码片段偏差更明显。
- 工具参数增量包含 JSON 结构与转义字符，估算值通常偏高。
- 服务端时间戳来自消息片段，网络抖动会计入耗时。
- 精确值只包含输出与推理 token，不包含输入与缓存部分。

因此实时值用于观察生成节奏，步骤结束后的数值用于判断实际吞吐。
